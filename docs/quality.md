# 高质量文章：各节点的验收与防护

质量由三层共同保证：**提示词约束**、**确定性检查**、**审核闸门**。
只靠模型自评会放过明显缺陷，因此所有客观信号集中在
`backend/app/article_generation/quality.py`，由各节点复用。

## 确定性检查

| 检查 | 作用 |
| --- | --- |
| `analyze_evidence` | 来源数、事实数、可追溯比例、高可信来源数、域名多样性、单一来源风险 |
| `analyze_draft` | 字数与目标偏差、二级章节数、引用总数、无效序号、引用覆盖率、无引用章节 |
| `validate_title` | 标题长度、平台上限、标题党措辞 |

平台标题上限：公众号 64、知乎/CSDN 100、掘金 80、其他 120 字。

## 节点行为

### 选题
- 沿用讨论度评分与硬性过滤；提示词要求候选必须能支撑 1500 字以上。

### 资料搜索
- Deep agent 提示词要求先拆问题、中英文各搜一次、阅读关键页面、交叉核对冲突、来源足够即停止。
- 搜索/抓取工具异常返回文本而不是中断整轮调研。
- 来源可信度域名表补充 python.org、CSDN、简书、人人都是产品经理等。
- Agent 只返回来源、没有返回事实时，自动用 `research.md` 补做一次事实抽取，避免证据丢失。
- 事实去重、过滤过短断言；`low_confidence` 由模型信号和确定性证据共同决定。

### 大纲
- 提示词要求核心论点、章节预算、来源序号只能引用真实来源。
- 服务端清洗空标题/重复章节、过滤越界 `source_refs`、字数限制在 400–6000。
- 没有有效章节时直接报错，不进入写作。

### 写作
- 提示词注入来源清单（含可信度）、事实状态、选题角度与写作技能。
- 明确引用纪律、verified 优先、冲突如实呈现、提交前自检。
- 生成后附上确定性质量提示（无效引用、覆盖不足、章节缺失、字数偏差）。
- 定向修订保留未涉及章节，并沿用原来源序号。

### 标题优化
- 提示词给出平台上限与标题党禁用词。
- 服务端过滤超长/标题党候选，推荐标题不合规则回退到评分最高且合规的候选。
- 用户手选标题同样校验长度与平台上限。

### 审核
- 提示词注入标题、大纲、来源、事实以及确定性检查 JSON；评分区间为
  80-100 可发布 / 70-79 合格 / 70 以下返工，minor 问题不重复扣分。
- 通过阈值读取设置 `review_pass_threshold`（缺失或非法时回退配置默认值）。
  总分达到阈值即通过；低于阈值但在 5 分容差内且没有 critical/major 问题也通过，
  避免小问题导致反复自动返工。
- 维度名称做中英文/大小写归一化，未识别维度不会覆盖有效分数。
- 确定性闸门（存在来源时）：
  - 没有任何有效引用 → fact 记 critical，直接判 fail，回滚研究；
  - 无效引用序号占比超过一半 → fact 记 major，直接判 fail；
  - 少量无效引用 → fact 记 major，分数上限 70，不阻断通过；
  - 标题超长或标题党 → compliance 记 major，直接判 fail；标题过短仅记 minor。
- 无来源场景不强制引用，避免离线/草稿模式误杀。
- 人工审批：设置中的 `auto_review_advance` 默认关闭，此时每次审核结束
  （无论自动结论通过与否）都会暂停为 `waiting_review`，在审稿面板选择：
  - **通过并继续**：无论自动结论如何都直接进入排版；
  - **驳回并重新生成**：必须填写意见；系统用 LLM 判断应回退到研究/大纲/写作
    （失败时按关键词兜底），记录到 `review_decisions`，不增加自动返工次数，
    并把意见注入后续提示词重新生成。
- 开启 `auto_review_advance` 后保持原自动行为：通过直接排版，未通过按自动
  回退目标返工，不出现人工闸门。

### 排版
- 产物正文或标题为空、标题超过平台上限时标记 failed，不进入发布。

### 发布确认
- `confirm-summary` 增加 `quality` 块：审核总分/结论、字数、引用统计、来源与事实数、
  `low_confidence`、标题问题与警告，供人工发布前验收。

## 模型调用防护

- 写作、审核、大纲的 `max_tokens` 默认提高（16384 / 12288 / 8192），避免 JSON 被截断。
- 结构化输出失败后的修复轮会带上**原始任务内容**，而不是只给 schema。
- 长文章和多次修订仍可能触发上下文/长度限制；失败会显式报错，不会静默产出空文章。
