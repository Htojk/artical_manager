# Spec Delta

## Purpose

约束资料搜索阶段对免费搜索引擎的调用频率，通过最小间隔、失败冷却、结果缓存与单次调用预算，降低触发验证码、限流或封禁的风险，同时保持搜索接口与降级行为不变。

## ADDED Requirements

### Requirement: 搜索引擎最小请求间隔
系统 SHALL 保证同一搜索引擎两次实际网络请求之间至少间隔配置的最小秒数；间隔内的请求 MUST 等待而不是并发发出。

#### Scenario: 连续调用同一引擎
- **WHEN** 一次调研在最小间隔内对同一引擎发起第二次搜索
- **THEN** 系统延迟到间隔满足后再发出网络请求
- **AND** 后续引擎与已有结果不受影响

#### Scenario: 不同引擎互不阻塞
- **WHEN** 当前引擎处于等待间隔，另一个尚未被调用的引擎可用
- **THEN** 系统可以立即调用该另一引擎而不必等待前一个引擎的间隔

### Requirement: 引擎失败冷却
系统 SHALL 在某个引擎请求失败后将该引擎标记为冷却状态；冷却期内 MUST 跳过该引擎，不再发起网络请求。

#### Scenario: 引擎返回限流或错误
- **WHEN** 某引擎返回 HTTP 错误、超时或解析失败
- **THEN** 系统记录冷却截止时间并继续尝试下一引擎
- **AND** 冷却期内的后续搜索直接跳过该引擎

#### Scenario: 冷却结束后恢复
- **WHEN** 冷却期已过且该引擎再次被选中
- **THEN** 系统重新允许对该引擎发起请求

### Requirement: 查询结果缓存
系统 SHALL 缓存成功返回的搜索结果；在缓存有效期内，相同引擎、相同查询与相同结果条数的请求 MUST 直接复用缓存而不发起网络请求。

#### Scenario: 重复查询命中缓存
- **WHEN** 同一查询在缓存有效期内被再次执行
- **THEN** 系统返回缓存结果且不产生新的引擎请求
- **AND** 返回结果的内容与首次一致

#### Scenario: 缓存过期后重新请求
- **WHEN** 缓存已超过有效期
- **THEN** 系统重新请求引擎并刷新缓存

### Requirement: 单次搜索调用预算
系统 SHALL 限制单次搜索调用可发起的引擎请求次数；达到上限后 MUST 停止发起新请求，并返回已收集的结果或明确的搜索失败错误。

#### Scenario: 预算耗尽但已有结果
- **WHEN** 单次搜索达到请求上限且已收集到至少一条结果
- **THEN** 系统停止继续请求并返回已有结果

#### Scenario: 预算耗尽且没有结果
- **WHEN** 单次搜索达到请求上限且没有任何结果
- **THEN** 系统返回搜索失败错误，研究阶段按既有逻辑降级为低置信度

### Requirement: 防护参数可配置且有安全默认值
系统 SHALL 通过环境配置提供最小间隔、缓存有效期、失败冷却时长与单次请求上限；未显式配置时 MUST 使用安全默认值，保证开箱即用。

#### Scenario: 未配置防护参数
- **WHEN** 部署环境未设置任何搜索防护配置
- **THEN** 系统启用默认的限流、冷却、缓存与预算策略

#### Scenario: 关闭缓存
- **WHEN** 缓存有效期配置为零
- **THEN** 系统不缓存结果，每次都发起引擎请求

### Requirement: 现有搜索行为保持兼容
启用调用防护后，系统 SHALL 保持搜索接口的输入输出与降级契约不变；自定义 JSON 搜索端点与 deep agent 的搜索工具 MUST 继续正常工作。

#### Scenario: 自定义搜索端点
- **WHEN** 配置了 `APP_SEARCH_ENDPOINT`
- **THEN** 系统仍优先使用该端点，防护逻辑不改变其请求与返回格式

#### Scenario: 全部引擎不可用
- **WHEN** 所有可用引擎均处于冷却或请求失败
- **THEN** 系统返回搜索失败错误，研究阶段继续执行并标记低置信度
