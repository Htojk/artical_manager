# Spec Delta

## Purpose

集中记录每篇文章在各平台的发布状态与表现数据，并把每次模型调用折算为 Token 用量与成本，为运营复盘和自进化提供可查询的事实基础。

## ADDED Requirements

### Requirement: 发布状态追踪
系统 SHALL 为每篇文章、每个平台维护发布状态（未发布/待确认/发布中/已发布/失败/已下线）及状态变更时间，状态变化 MUST 留下历史记录。

#### Scenario: 状态随发布更新
- **WHEN** 公众号发布成功后
- **THEN** 该文章在公众号下的状态变为「已发布」，并记录变更时间与操作来源

#### Scenario: 查看状态历史
- **WHEN** 用户查看某篇文章的发布状态
- **THEN** 系统展示每个平台的最新状态与完整的变更历史

### Requirement: 阅读量与收益采集
系统 SHALL 通过平台适配器或用户手动回填，按文章与平台记录阅读量、点赞、评论、分享与收益等指标，并为每次采集保存带时间戳的快照。

#### Scenario: 定时采集指标
- **WHEN** 到达配置的采集时间且平台接口可用
- **THEN** 系统抓取该平台文章的阅读量与收益并保存为一条快照

#### Scenario: 指标随时间增长
- **WHEN** 同一篇文章先后采集两次
- **THEN** 系统保留两条快照，可展示指标随时间的变化

#### Scenario: 接口不可用时手动回填
- **WHEN** 平台未提供可用的指标接口
- **THEN** 用户可以手动录入阅读量与收益，系统按快照保存并标记来源为「手动」

### Requirement: Token 用量与成本台账
系统 SHALL 记录每次 LLM 调用的供应商、模型、输入/输出 Token 数、单价与折算成本，并能按文章、阶段、模型与日期聚合。

#### Scenario: 记录单次调用成本
- **WHEN** 写作阶段调用模型完成一次生成
- **THEN** 系统写入一条调用记录，包含模型、Token 数与本次成本

#### Scenario: 按文章汇总成本
- **WHEN** 用户查看某篇文章的成本
- **THEN** 系统展示该文章各阶段、各模型的 Token 用量与总成本

#### Scenario: 未知模型价格
- **WHEN** 调用的模型未在价格表中配置
- **THEN** 系统仍记录 Token 用量，并将成本标记为「价格未配置」而非写入错误数值

### Requirement: 模型价格配置
系统 SHALL 允许维护 OpenAI 兼容模型的输入/输出单价与生效时间；成本计算 MUST 使用调用发生时生效的价格。

#### Scenario: 调整模型价格
- **WHEN** 用户修改某模型单价并设置生效时间
- **THEN** 之后发生的调用按新单价计费，历史记录保持不变

### Requirement: 文章表现与成本对照
系统 SHALL 提供按文章对照展示阅读量、收益、总成本与单位收益成本的能力。

#### Scenario: 查看投入产出
- **WHEN** 用户打开运维分析看板
- **THEN** 系统按文章展示阅读量、收益、总成本与收益/成本比
