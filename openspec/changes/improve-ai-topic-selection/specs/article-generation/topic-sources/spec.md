# Spec Delta

## Purpose

从可配置的 RSS/Atom 与 HTML 列表页获取热点信号，并只在需要时把单篇文章解析为可复用的正文来源，为选题与资料研究提供一致、可去重的输入。

## ADDED Requirements

### Requirement: 可配置的 RSS 与 HTML 热点信源

系统 SHALL 支持 RSS/Atom 与 HTML 列表页两类热点信源。每个来源包含名称、类型、URL；HTML 来源还可配置条目、标题与链接选择器。未配置任何来源时，系统 SHALL 默认使用量子位 RSS `https://www.qbitai.com/feed`。

#### Scenario: 解析 RSS 来源
- **WHEN** 来源类型为 RSS 且返回合法的 RSS/Atom 文档
- **THEN** 系统提取每个条目的标题、链接与发布时间，并作为热点信号返回

#### Scenario: 解析 HTML 列表页
- **WHEN** 来源类型为 HTML 且配置了条目与标题选择器
- **THEN** 系统按选择器提取每个条目的标题与绝对链接，并作为热点信号返回

#### Scenario: 单个来源失败被隔离
- **WHEN** 多个来源中有任意一个超时、返回非 2xx 或内容无法解析
- **THEN** 系统记录该来源的错误并继续返回其他来源的信号，不中断选题推荐

#### Scenario: 默认信源
- **WHEN** 用户未配置热点信源
- **THEN** 系统使用量子位 RSS 作为默认来源

### Requirement: 标题级热点信号

系统 SHALL 将热点信号限制为标题、来源名称、链接、发布时间与顺序标识，MUST NOT 在推荐或列表接口中返回文章正文。

#### Scenario: 信号不含正文
- **WHEN** 系统完成一次热点抓取
- **THEN** 每条信号只包含标题、来源、链接、发布时间与顺序标识，不包含文章正文

#### Scenario: 信号去重
- **WHEN** 多个来源返回标题相同或大小写/空格差异后相同的条目
- **THEN** 系统只保留一条信号，并优先保留来源顺序靠前的一条

### Requirement: 单篇文章正文提取

当用户选定与某条热点信号关联的选题时，系统 SHALL 抓取该信号的文章链接，提取正文文本并保存为与当前文章关联的资料来源；抓取或解析失败 MUST 只记录错误，不得阻断选题确认。

#### Scenario: 成功提取正文
- **WHEN** 用户选定一个关联了文章链接的候选选题
- **THEN** 系统抓取该链接、提取正文并保存为来源，来源标记为选题预抓取且与文章关联

#### Scenario: 抓取失败不阻断
- **WHEN** 关联文章超时、返回错误或无法提取正文
- **THEN** 选题仍然确认成功，系统记录抓取错误并在选题响应中返回该错误

#### Scenario: 重复链接不重复入库
- **WHEN** 同一链接已作为来源存在
- **THEN** 系统复用已有来源，不再新增重复记录

#### Scenario: 遵守 robots.txt
- **WHEN** 目标站点的 robots.txt 禁止抓取该链接
- **THEN** 系统不抓取正文，按抓取失败处理并记录原因
